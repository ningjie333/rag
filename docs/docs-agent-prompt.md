# 文档 Agent 任务提示词

## 任务目标

为"学科知识整合智能体"编写缺失的 3 个核心文档。

## 项目背景

- 前后端 API 已完成（8个端点）
- 图谱可视化、RAG 问答、多轮对话已完成
- 已有 `docs/Agent架构说明.md`

## 交付物（3 个文档）

### 1. `docs/需求分析.md`

**内容要求：**
- 项目目标：7本教材 → 知识图谱 → 跨教材去重（≤30%）→ RAG 问答
- 问题分解：
  1. 如何从 PDF 提取结构化知识（知识点、关系）
  2. 如何构建知识图谱（节点、边、权重）
  3. 如何跨教材去重合并（语义对齐、压缩比量化）
  4. 如何实现带引用的 RAG 问答（精准引用来源）
  5. 如何生成可读的整合报告
- 用户场景：学生备考、教师备课、自学
- 功能列表：上传教材、查看图谱、提问、对话、导出报告

### 2. `docs/系统设计.md`

**内容要求：**
- 系统架构图（前端 Vue3 / 后端 FastAPI / 向量库 ChromaDB）
- 模块说明：
  - PDF 解析模块（pymupdf + langchain）
  - 知识点提取模块（LLM prompt engineering）
  - 关系推理模块（多信号 + LLM）
  - 图谱构建模块（去环、去重、权重）
  - RAG 检索模块（向量检索 + hybrid）
  - 对话管理模块（会话历史）
- 数据流：从 PDF → 分块 → 嵌入 → ChromaDB → 图谱构建 → RAG → 回答
- 接口清单（参考 `docs/api-contract.md`）

### 3. `report/整合报告.md`

**内容要求：**
- 以 3-5 个知识点为例，展示整合效果
- 格式：Markdown
- 必须包含：
  - 各教材原始知识点数量
  - 整合后知识点数量
  - 压缩比（≤30%）
  - 去重示例（同一概念不同教材的不同表述）
  - 跨教材关系发现
- 示例结构：
```markdown
# 知识整合报告

## 整合概览
- 原始知识点：150 个
- 整合后知识点：42 个
- 压缩比：28%

## 去重示例
### 示例 1：细胞呼吸
- 教材A：细胞呼吸是细胞利用氧将葡萄糖转化为二氧化碳和水的过程...
- 教材B：呼吸作用是生物体分解有机物释放能量的过程...
- **合并**：统一为"细胞呼吸/呼吸作用"，标记为同义词

## 跨教材关联
- "光合作用"和"细胞呼吸"互为逆过程（教材1 & 教材3）
```

**注意**：用 mock 数据或 LLM 生成示例内容，不需要真实教材数据。

## 验收标准

1. `docs/需求分析.md` 存在，≥500 字，有结构（标题/列表/表格）
2. `docs/系统设计.md` 存在，≥500 字，有架构图描述
3. `report/整合报告.md` 存在，≥300 字，有具体数字示例

- ❌ 不编造 API 响应（参考 `docs/api-contract.md`）
- ❌ 不做技术深度分析（只做基础描述）
- ❌ 不写测试
