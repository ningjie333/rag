## 错误根因

**直接原因：** `kg_extractor.py` 第297行
```python
nodes_list = "\n".join([f"- {n['name']}: ..." for n in merged_nodes[:50]])  # ← BUG
```
阶段2全局关系推理只传入了前50个节点（共6297个），LLM在50个节点的盲区里推理出17条边。

**漏检原因：**
1. 小规模测试（100 chunks）生成的文本高度重复，200 raw nodes → 2 merged，[:50]时只拿到2个节点，无法暴露此bug
2. 大型任务未执行"中途验证协议"：全程无中间检查，等全部跑完才发现问题

---

## 改进措施

### 1. 大型任务执行规范

**判断标准：** 预估时长 ≥ 30min → 触发大型任务协议

| 阶段 | 操作 |
|------|------|
| 启动时 | 预估总耗时，告知用户 |
| 阶段1完成后 | **必须验证中间输出**：节点数量级、边数量级是否合理 |
| 阶段2完成后 | 最终验证，不等到全部完成 |

### 2. 测试规范

- 小规模测试必须使用**真实数据**（非生成重复文本），才能暴露节点数差异
- 大规模验证前，用中等规模（50-100 chunks）真实数据做 smoke test

### 3. 代码规范

阶段2传入节点数必须明确记录和限制：
```python
# BAD
nodes_list = "...\n".join([f"- {n['name']}..." for n in merged_nodes[:50]])

# GOOD
nodes_sample = merged_nodes[:50]  # 显式命名，明确意图
# 或分批处理 + 合并结果
```
