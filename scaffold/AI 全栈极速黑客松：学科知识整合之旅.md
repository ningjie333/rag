## 3\. 详细总结（分点 \+ 表格 \+ 关键数字加粗）

### 一、赛事基础概况

1. **赛事主题**：开发**学科知识整合 AI 智能体**，解决高校同学科多本教材内容冗余、重复阅读、教学评估无数据支撑的痛点。

2. **核心任务**：把**7 本教材**整合精炼为不超过原始体量**30%** 的精华内容，保证教学效果不下降。

3. **比赛时长**：固定**5 小时**极速开发。

4. **测试数据**：赛方统一提供**7 本专业教材**，需以此生成标准整合报告。

### 二、功能分级要求

#### 1\. P0 必做功能（核心验收项，共 10 项）

1. **多格式教材加载解析**

    - 必支持：**PDF、Markdown、TXT**；建议支持**docx**，可选 Excel。

    - 前端支持批量拖拽上传，展示文件信息与解析状态；输出固定结构化 JSON。

    - PDF 需过滤页眉页脚、识别章节、跳过图表，大文件**逐页解析**防内存溢出。

2. **单本教材知识图谱构建**

    - LLM 按章节提取**概念 / 定理 / 方法**等知识点，输出标准化节点 JSON。

    - 知识点关系至少实现 4 类中**3 种**：前置依赖、并列、包含、应用关系。

    - 输出标准化边结构，支持 Few\-shot Prompt 约束 JSON 格式。

3. **知识图谱交互**

    - 支持节点点击查详情、**节点大小 / 颜色映射知识点出现频次**、不同教材分色标识。

    - 基础缩放、拖拽、节点移动；推荐**D3\.js/ECharts/AntV G6/Cytoscape\.js**。

4. **跨教材知识图谱整合（核心难点）**

    - 采用**Embedding 语义相似度 \+ LLM 判断**做知识点语义对齐。

    - 支持 merge 合并、keep 保留、remove 删除三类整合决策。

    - 严格控制**压缩比≤30%**，前端展示压缩统计，支持整合前后图谱对比。

5. **RAG 精准问答**

    - 分块：**500–800 字 / 块**，重叠**50–100 字**，保留教材章节页码元数据。

    - 向量库推荐**FAISS/ChromaDB**，支持本地 sentence\-transformers 中文嵌入模型。

    - 回答**必须引用原文来源**，无相关内容则固定话术回复；加分可做向量 \+ BM25 混合检索 \+ Rerank。

6. **Agent 架构设计**

    - 自主设计单 / 多 Agent 架构，必须提交**Agent 架构说明\.md**。

    - 内容含：架构总览、设计决策论证、数据流链路、方案取舍与局限改进。

7. **多轮对话迭代**

    - 自然语言对话修改整合决策，系统解释合并 / 删除理由，修改后**实时更新图谱**。

    - 对话历史持久化保留上下文。

8. **Web 单页应用界面**

    - SPA 布局：左侧教材管理、中间图谱可视化、右侧功能 Tab 面板。

    - 适配**1920×1080**分辨率浏览器访问。

9. **整合报告输出**

    - 输出 Markdown 报告，含压缩比、整合决策统计、图谱节点变化、典型案例、教学完整性说明。

10. **全套开发文档**

    - 必须包含：需求分析、系统设计、Agent 架构说明、README，目录按规范存放。

#### 2\. P1 加分项（自愿实现，额外加分）

多视图图谱切换、图谱拖拽编辑整合决策、混合检索 \+ Rerank、Token 消耗可视化、Ollama 本地开源部署、报告 PDF 导出、Docker 一键部署、自建 RAG Benchmark 量化优化等。

## 4\. 三个关键有价值问题 \+ 答案（不同侧重）

### 问题 1（任务核心侧重）：本次黑客松赛题的核心技术难点和硬性指标是什么？

**答案**：核心技术难点是**跨教材知识点语义对齐与去重整合**，需解决不同教材同义不同表述的知识点匹配、冗余合并；硬性指标有：比赛时长**5 小时**、整合后内容体量≤原始**30%**、必须基于**7 本指定教材**生成整合报告、RAG 问答**每条回答必须附带教材原文引用**、需自研并提交**Agent 架构说明文档**。

### 问题 2（开发落地侧重）：P0 必做功能中 RAG 模块的标准 Pipeline 和分块参数要求是什么？

**答案**：标准 Pipeline 为**文档分块→向量嵌入→向量库存储→相似度检索→LLM 生成带引用回答**；分块要求：单块**500–800 字**，块间重叠**50–100 字**，每个块必须保留教材名、章节、页码元数据；推荐使用中文 BGE/sentence\-transformers 嵌入模型，向量库选用 FAISS/ChromaDB，加分可实现向量 \+ BM25 混合检索与 Rerank 重排序。

### 问题 3（提交评分侧重）：参赛必须提交哪些材料？评分中 Agent 架构维度的评判标准是什么？

**答案**：①必交材料：**公开 GitHub 仓库链接 \+ 公网可访问 Web 部署链接**，缺一不可；P2 技术报告为选填，可赛后 24 小时补交。②Agent 架构评分不看 Agent 数量，只看**架构设计合理性、文档论证深度**，需包含架构总览、设计决策理由、数据流链路、方案取舍与局限改进；有 Mermaid 架构图、量化实验数据支撑可拿进阶高分。
